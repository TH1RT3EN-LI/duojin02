# 输入、恢复与结果边界检查

本轮以 `4dea743` 为基线，修正实际复现的接口与生命周期问题。规划、控制、SLAM、碰撞和制动数学及其配置值不变。

| 发现 | 当前处理 |
| --- | --- |
| 扫描有效期 300 ms，但内部 TF 只等 20 ms，并在两帧队列中丢弃仍有效的扫描；定位变换未就绪时也提前移除候选 | 删除独立 TF 短期限与重复队列；按同一扫描源时间和接收时间有效期保留待处理帧，所需扫描与定位变换齐全后处理，过期即丢弃 |
| 全零里程计四元数会被解释成零朝向；不合法纳秒字段可能被隐式合并成时间 | 在输入边界拒绝不可用四元数和非法时间字段，不添加定位质量阈值 |
| BT 在处理回包前判定期限，丢弃预算内已返回的数据 | 先处理就绪回包，期限限制继续等待；请求终止后迟到回复不复活它 |
| 周期规划更新黑板，导致恢复误判旧路径已变或新路线与旧路线相同 | 以本次检查的 `checked_path` 为比较基准；同一目标的新规划不撤销证据，目标切换仍取消旧请求 |
| OS 信号提前关闭 ROS，最后零速度发送失败；长轮询退出后终端仍为 raw | 主线程统一处理信号和 ROS，TTY 使用可唤醒的等待；工人线程退出、零速度发出、终端恢复后关闭 ROS，删除轮询时间参数与第三个线程 |
| 手柄长按时间跨断流、旧帧或按钮数组缩短累积；非法配置被默默修成零 | 使用共同命令有效期检验新鲜输入，清除中断的按键状态；非法长按和反馈配置在启动时报错 |
| 地图清单核对了另一张地图；未消费的位姿图损坏也阻断栅格导航 | 清单必须绑定当前 YAML/图像及必需角色；栅格导航只核对消费文件，续建额外核对配对位姿图 |
| 保存失败或 SLAM 后端异常退出被外层 launch 报成成功 | 子进程非零退出使相应 launch 返回非零；保存失败不触发手柄成功反馈，损坏图拒绝也有明确失败状态 |
| 同名录包复用旧元信息目录，混入旧参数 | 原子预留新 sidecar，已有目录拒绝且不修改，保留记录器真实退出码及正常数据库收尾 |
| 布尔起始坐标被转成数值，无效 dock 字符串被默默当作 false | 拒绝错误类型；合法数值坐标和布尔开关输出不变 |
| 构造时读取的参数允许动态设置返回成功，运行成员却没有更新 | 静态参数声明只读；启动 YAML/CLI 覆写仍可用，Nav2 本来支持的动态参数保持原接口 |

速度保护的扫描等待在现有单线程执行器内完成；缓存只保留仍符合源时间与单调接收时间的帧。扫描消失、重复或超时不能延长指令有效期，格式无效仍立即停车。100/200 ms 的合成扫描 TF 延迟和 100 ms 定位 TF 延迟能够持续处理，400 ms 超期仍停止；这些结果不是实物停车时间。

键盘按键加减速与控制核心不变。信号退出验证覆盖活动和闲置的 SIGINT/SIGTERM；活动来源发最后一次零速度，闲置来源保持安静。手柄任务按钮只在连续有效输入达到既有长按时间后触发，保存进行中仍忽略重复触发。

检查使用真实 ROS 服务/动作、正式行为树、PTY 和真实 CUDA，合成数据与受控规划/控制响应用于验证边界。没有移动实物机器人；没有以未标定评分、协方差或计算时长添加停车条件。
