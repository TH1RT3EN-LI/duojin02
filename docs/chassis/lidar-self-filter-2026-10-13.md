# 底盘近距回波裁剪：筛查、实现与验证

2026-10-13。只处理底盘。已有社区几何自过滤机制适合偏置雷达和非圆形底盘；本轮把关键的数据处理顺序补进本地 N10Plus 驱动，并保留校准与仿真证据的边界。


仿真曾按硬件 Xacro 对齐到 130.233 mm，之后按用户要求恢复到 143.308 mm；硬件元数据仍为 130.233 mm，sensor、TF 和裁剪有效外参同步覆盖仿真 Z。本文 464 帧回放属于原历史捕获，不替代最新闭环结果。[高度恢复](/home/th1rt3en/Documents/Codex/2026-10-13/outputs/sim-height-restoration-20261013/report.md)、[位姿对齐的原记录](sim-hardware-alignment-2026-10-13.md)。

## 结论

`min_range=0.3` 是以雷达为原点的量程过滤，不能代表机械自过滤。底盘自身判定应该独立使用准确的实体模型和雷达外参。导航 footprint、安全膨胀和粗 collision box 都不能直接作为光学实体。

ROS 2 `laser_filters` 已有基于 TF 的多边形过滤；URDF 实体过滤还有 ROS 2 候选包。原始论文也记录过大的机器人凸包误删外部物体的实例。本场需要准确几何和正确处理顺序，没有证据支持先引入学习模型。[社区与论文筛查](lidar-self-filter-sources-2026-10-13.md)。

当前驱动解码两个 echo 后，在 LaserScan 中选择每个 bin 的最近点。若最近点来自自身，之后再过滤单值 `/scan`，外部第二 echo 已不可恢复。因此实现的顺序为：

**传感器有效量程检查 → 保留全部可用 echo → 外参变换和底盘实体判定 → 保留模糊边界 → 在保留 echo 中选最近点。**

没有检测到 echo 不意味着能凭空恢复它；这里保证已经解码到的外部第二 echo 不因最近自身 echo 被覆盖。

## 本地实现

- [独立 C++ 几何接口](../../src/lslidar_driver/lslidar_driver/include/lslidar_driver/self_filter.hpp)：明确的 XYZ/RPY、简单凹多边形、有限 Z 范围。只删除严格位于实体内部且离边界超过歧义带的点；边界点保留。拒绝缺失/非有限姿态、无高度范围、退化、自交与重叠边。
- [驱动集成](../../src/lslidar_driver/lslidar_driver/src/lslidar_x10_driver.cpp)：在双 echo 合并前逐点判定；过滤后的点云与扫描使用同一数据。仅有被几何删除 echo 的 bin 输出 NaN，表示未知；不将自身删除伪装成后方空闲。
- 可选 `/lslidar_point_cloud_raw` 保留全部量程内 echo；`/scan_raw` 保留未做几何过滤的最近 echo。原始与过滤数据使用同一个采集时间戳、坐标系、角度和扫描周期。解析 ROS namespace/remapping 后检查话题冲突，防止 raw 与 filtered 混流。
- [参数和模型约束](../../src/lslidar_driver/lslidar_driver/SELF_FILTER.md)。固定外参在初始化时计算；模型/安装变化需重新配置和重启。未实现动态部件、孔洞、多块不连通实体或运行时 TF 自动查找。

边界三态是本项目偏向保留外部点的工程策略；歧义带不能被称为已经实测的误差界，保留模糊点也可能保留自身噪声。需要分别测外部误删与自身漏删。

初始能力实现默认不开启几何掩膜，也不自动载入任何导航轮廓。当时量程配置未调整；raw 输出位于 min/max 检查之后。后续用户已要求实现投影裁剪并暂时忽略安装朝向偏差，当前配置见下方“本轮启用配置”，不能把本段初始状态当作当前参数。

## 模型审计发现

本次捕获 URDF 与实际 raw sensor SDF 自洽：光学平面 Z 为 0.14330766582 m。当前硬件 xacro 代理高度为 0.1302326658155 m，相差 13.075 mm，测量文件明确光学高度尚未标定。

两个原点都在导航 collision 大盒子内。该盒子含空腔，不能当作实心光学模型；若用其做 shadow test，会造成全方向从所谓实体内部出发。视觉 CAD 的部分网格还有边界边和非流形边，也不能自动当作闭合实体。

此外，本次捕获的扫描平面高于底盘壳体最高点约 11 mm；当前硬件代理平面仍与壳体相交。用同一全高度 XY 投影不能证明两次扫描的自身实体一致。

[可复现模型审计](/home/th1rt3en/Documents/Codex/2026-10-13/outputs/chassis-self-filter-research-20261013/model-audit/report.md) 包含脚本、各源文件 hash、平面截面和拓扑统计。最近 CAD 表面不是有效光学量程或不透明遮挡的实测证明。

## 剩余实际验证

实机启用准确自掩膜仍需要扫描平面高度、外参和能被照到的底盘实体截面；不能用上述大盒子或整个导航八边形代替。初始阶段只有底层过滤能力和离线验证。后续已有原生几何耗时测量及本轮投影排除策略配置；仍没有实机过滤身份真值；后续严格投影裁剪的仿真闭环修复验证见下方当前配置。

调整量程时应同步完整消费者契约：初始驱动和 AMCL 为 0.30 m，SLAM Toolbox 为 0.31 m；本轮一起改为 0.02 m。只改驱动不能保证定位使用新增近点。常规仿真验收的 0.60 m 下限和原安全余量保持独立。

后续标定数据需要同时保留原始双 echo、过滤分类和具体底盘外近墙/薄杆真值，分别统计外部点误删、自身点漏删与时间开销，再验证健康判据和闭环行为。

## 真机接收补充：投影外线缆必须保留

用户明确现有电线、网线有部分伸出底盘投影，不应删除。2026-10-13 已完成 15 秒接收式原始串口采集，149 圈完整扫描；不执行设备命令、量程门、强度门、邻域去噪或几何掩膜。158,720 条双回波记录与实际 C++ 驱动解码逐条一致。按当前模型投影标注，323 次外部回波距离为 167–299 mm，均保留；它们会被旧 0.3 m 量程门删除，但尚未与实物线缆身份对应。

这一数据保留结果属于原始采集阶段，不能单独宣称 ROS 链已修复：采集时驱动 min_range 为 0.3 m，raw ROS 话题在该门之后；本轮配置与实际驱动离线回放另行验证。线缆不能因靠近底盘、低强度、点数少或多圈持续出现便被认作自身。数值边界标签不是实测误差界，未确认点继续保留。完整双回波使用点云或 CSV 检查，不能用每角度槽最近点的 LaserScan 代替。

## 本轮启用配置：投影排除策略

用户要求实际实现裁剪，并明确暂时忽略雷达当前朝向不正的问题。因此硬件 `duojin01_n10plus.yaml` 显式启用过滤，沿用模型 yaw=0 及完整安装 XYZ；未拟合或写入 +3° 假设。选择未膨胀底盘八边形投影作为明确的排除区域，而不是宣称它是已标定的光学实心材质。机械臂与上部结构不参与。当前 `boundary_ambiguity_m=0.0`，所有严格投影内部回波裁掉，外部有效点和数值意义上的精确边界保留，不外扩删除。

此前的 3 cm 内侧保留带与用户“投影内部裁掉”的要求冲突，已取消。它曾让少量内部回波进入障碍记忆，并在后续 NaN 扫描中残留，造成 60 cm 起点保护停车。[原版 Jetson 保护器因果验证](/home/th1rt3en/Documents/Codex/2026-10-13/outputs/corner60-failure-verification-20261013/report.md)。通用几何 API 仍可显式配置非零 band，历史实验数据仍保持其原输入契约。

当前严格策略已通过 28 项 C++ / 41 项仿真测试、149 圈实际驱动发布回放；原版 ARM 保护器接受 245 帧新裁剪输入，400 次保护检查全部 clear，内部记忆为零。Jetson 算法下 60 cm 转角 seed21/22 均严格到达（10.403 / 10.363 s、误差 5.407 / 6.597 mm、碰撞零），原始投影外点全部保留。只验证该仿真场景，未启用真机驱动或重跑 50 cm。[本次修改及完整证据](/home/th1rt3en/Documents/Codex/2026-10-13/outputs/chassis-projection-crop-correction-20261013/report.md)。

N10Plus driver 缺省及硬件 YAML 的有效量程下限从 0.30 m 改为 0.02 m，AMCL 两份配置及 SLAM Toolbox 同步。两回波先分别判定再选最近保留返回；只删掉自身候选返回且没有剩余返回的方向输出 NaN。定位健康检查把部分 NaN 当作未知方向跳过，不产生任何地图证据，也不换用临近束补齐固定抽样。最少有效观测数、TF/时间要求和异常负无穷/非法近距拒绝保持。

诊断默认打开 `/scan_raw` 和 `/lslidar_point_cloud_raw`，后者保留两回波，均只受 2 cm 有效量程门约束；不会把投影外的电线因低强度、孤立或持续出现而删除。当前模型朝向下的外部保留由回放检验，物理方向偏差仍按用户要求暂不修正。

Top1 的 AMCL 输入范围随之更新，本地 release manifest 只更新 profile hash 并记录之前的配置/manifest 快照；所有算法二进制、控制器参数与环境 pins 保持。旧实测延迟属于之前的输入契约，不能用作此次改动的完整导航性能测量。
