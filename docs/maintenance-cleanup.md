# 结构清理与参数入口（2026-10-13）

本轮以当前工作树冻结提交 `f90a30c` 为基线，按静态审查修复输入边界、状态恢复、测试隔离及维护结构。既有未提交的导航修复先完整保存，再执行清理。规划、采样、轨迹跟踪、制动扫掠、空间索引、关联缓存和 SLAM 后端算法保持原实现；生产参数数值不调整。

## 参数维护

持久参数的完整表在[开发接口](../README_DEVELOPMENT.md#配置与模型边界)。导航、SLAM、固定图质量报警、停车保护、底盘反馈与雷达各由其明确配置文件维护。键盘节点和纯控制核心共同读取 `keyboard_teleop_defaults.py`；质量模型和监视器共同读取 `localization_monitor.yaml`；Guard 与底盘的共同命令超时在 `safety.yaml`。后续停车逻辑精简见 [停车保护](safety.md)。

在线导航只传递所选配置，`online_profile` 根据实际 `slam_params_file` 统一派生地图分辨率和 lattice，并维护在线未知区域策略。默认派生结果与基线最终有效 YAML 完全一致，另验证改变 SLAM 文件会同步改变关联派生配置。控制器限速和平滑器输出约束、各节点频率、保护余量与 costmap padding 有独立语义，仍在各自所属入口维护。

没有添加第二套参数格式。Humble 原生 RCL 参数解析器实际拒绝 YAML alias；PyYAML 能解析并不能证明节点能加载。ROS 当次覆盖可用于实验，经过验证的持久调整回写配置入口。`settle_time` 明确为只读启动参数，保留默认值和显式启动覆盖值。

## 审查项目的处理

| 项目 | 处理 |
| --- | --- |
| 两项探针可能接入在线 DDS 图 | 共用初始化前隔离工具，本机域保留锁，子进程继承；统一命令链入口 |
| 非法地图后原图被签名去重 | 地图对象与签名一起失效，恢复原图仍需重新获得健康许可 |
| Guard 的地图 / TF 非有限或索引越界输入 | 独立入口校验，坏图闭锁、合法图恢复；原数学 helper 不变 |
| 在线 SLAM 参数来源脱节 | 按实际选择的配置派生，外层显式转发 |
| 干净 Docker 回归缺少固定源码 | 新增 testing 目标冻结源码；只读检查版本、补丁 SHA 和补丁内容 |
| 旧地图同步及空 maps 安装项 | 删除；工作区 maps 继续作为保存 / 选图位置 |
| Foxglove 空布局及无输入 Image 面板 | 删除 JSON 与安装项；保留实际 bridge |
| RViz 全局图订阅错误和旧模型条目 | 修正全局图与透明度，清理旧 frame，匹配晚加入 QoS |
| 空轮轴中间层的历史名称兼容 | 合并为连续轮关节；轮子位姿、轴向、几何、足迹不变 |
| CAD 生成器一次性膨胀调参 | 删除；生成器只更新其几何 / 足迹职责 |
| 可写却不动态生效的 settle_time | 只读启动声明；不改变停稳判定 |
| TODO / 未使用导入 | 清理 |
| SIGINT 后向已关闭 context 发布 | 修复退出生命周期；严格检查子进程正常退出 |

停止状态位姿协方差中的微小非对称项保持原值。修正它涉及反馈数值契约，超出本轮“不改算法和数值”的范围；当前 EKF 只融合速度。MPPI 的错误 fallback、仍被使用的 Humble 适配和离线旧录包支持也保留，不根据代码外观删除其行为。
