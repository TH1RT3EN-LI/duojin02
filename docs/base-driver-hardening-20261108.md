# 底盘反馈与 IMU 发布加固（2026-11-08）

本轮针对没有新实车录包时可验证的软件问题，先隔离比较，再安装到本机 CUDA 工作区。
旧版基线为 `fb0007a00c745938461642c945da048d7e60b5a5`；两版均使用
`duojin02:hardware-humble` 镜像中的 ROS 2 Humble 和串口依赖，实际启动 C++ 节点，
通过 PTY 发送底盘协议字节。测试不连接物理串口。

## 修改

- 用有界 FIFO 替代单份“最新帧”。默认容纳 256 帧，每个定时回调最多处理 16 帧，
  溢出时丢最旧帧并累计计数。发生序号缺口后不跨缺失区间积分。
- 校验失败后从缓冲区内下一个帧头恢复，避免错误前缀吞掉紧随其后的完整好帧。
- 校验 IMU 零偏为有限数、方差为有限正数、里程计方差恰有六项且均为有限正数，
  同时检查循环频率、波特率、缩放及队列/诊断参数。非法配置在打开串口前明确报错退出。
- 姿态更新返回成功状态。首帧、非正时间步、过大时间步、队列丢帧等情况下，
  未更新的姿态通过 `orientation_covariance[0] = -1` 标记无估计；有效陀螺仪测量仍正常发布。
  此标记遵循 [ROS 2 Imu 消息合同](https://github.com/ros2/common_interfaces/blob/humble/sensor_msgs/msg/Imu.msg)。
- `/diagnostics` 新增接收、发布、排队、溢出、连接重置丢弃、校验错误、时间异常、
  姿态更新状态、最大排队延迟等计数。退出时先关闭串口并等待 I/O 线程，避免回调访问已析构状态。

正常输入下的解码、零偏减法、轮速缩放、积分公式、姿态滤波增益及有效测量协方差保留。
当前 `ekf.yaml` 仍只使用 IMU 的 Z 角速度；没有接入 IMU 姿态和线加速度。
本轮没有从无数据条件下估计新零偏、调整融合权重或开启在线自适应。

## 对比结果

| 场景 | 旧版 | 新版 |
| --- | --- | --- |
| 18 帧受控正常输入 | 作为数值基线 | 时间戳、测量、姿态、里程计及融合协方差逐项相等；首帧姿态可用性标记按上述合同变化 |
| 5 组 × 12 帧突发，每组一次写入 | 每组仅发布 1 帧 | 每组按原顺序发布 12 帧，无重复 |
| 错误前缀紧接完整好帧 | 好帧丢失 | 恢复并发布 1 帧 |
| 容量 16，突发输入 80 帧 | 仅保留最新帧，无丢弃诊断 | 发布最近 16 帧、计数丢弃 64 帧，高水位 16，计数守恒，不跨缺口积分 |
| 同时刻、时钟倒退、过大时间间隔 | 继续发布旧姿态并附原方差 | 姿态标为不可用；正常时间步后恢复 |
| 11 组非法启动参数 | 未统一拒绝 | 全部在串口初始化前拒绝 |

在第一版和第二版候选上均复现上述结果；补齐线程退出与启动错误处理后，再对最终驱动重复验证。
测试初版曾因 DDS 发布者已发现、串口尚未就绪而超时；探针现先在相同测试时刻确认接收就绪，
再开始计量，不通过延长生产超时或修改被测数据取得通过。

另外，原有 PTY 回归在两版均通过：10 Hz 反馈对应的路程/接收时间比约为 1，
自定义波特率、标定参数、坏校验拒绝、命令编码/限幅、非法速度归零、约 0.25 秒指令超时停车、
静默断流重连和正常退出保持有效。候选版另通过 19 项启动参数及运行检查、
`feedback_pipeline_checks` C++ 检查和 429 项 Python 回归；Python 有一条上游 xacro 兼容性警告。

## 参数与观察

| 参数 | 默认值 | 约束 |
| --- | --- | --- |
| `feedback_queue_capacity` | 256 | 启动只读，整数 1–4096 |
| `diagnostic_hz` | 1.0 | 启动只读，有限数且 0 < Hz ≤ 100 |

在所选 Humble 环境中可通过 `ros2 topic echo /diagnostics` 查看 `base_driver/feedback`。
无反馈超过原有 0.5 秒阈值时仍触发停车和重连。累计收到的帧数应等于已发布、仍排队、
溢出丢弃和重置丢弃之和；最大排队延迟用于判断消费是否跟得上接收。

## 结论边界

已验证的收益是避免驱动内部静默覆盖、改善错帧恢复，并使丢弃和无效姿态可观测。
协议没有设备采样时间或设备序号，队列保存的仍是主机接收时间；突发帧的真实采样间隔无法
由此恢复。受控 `/clock` 只用于确定性软件比较，不证明真实积分精度。

现有有效姿态/加速度固定方差及可配置陀螺仪方差仍未经过实测标定，诊断明确标记
`orientation_covariance_calibrated = 0`。姿态相对积分没有绝对航向观测；本轮没有实现统计一致的
协方差传播。没有实车数据，不能承诺定位误差降低，也不能证明所有运行条件都不退化。
这轮通过后部署的是已测的软件加固，不构成整机精度验收。
