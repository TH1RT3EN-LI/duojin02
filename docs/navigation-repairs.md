# 导航修复与回归检查

本页维护当前 Humble 插件的行为契约；继续保留现有 SLAM Toolbox、AMCL 与导航接口。新模块对照尚不足以支持整套替换，已有结果和候选范围见 [优化状态](navigation-optimization.md)。

## 控制和制动

`PreciseMPPI` 的确定性跟踪、停靠和原生 MPPI 输出均应用同一组速度限制。百分比和绝对值请求同时按比例限制前进、后退、横移和转动；零值恢复配置上限，非法请求闭锁。动态配置变化会刷新限制，原生优化器周期重置后重新应用限制，所有最终输出再次裁剪。

该保证针对发出的速度命令。原生优化器内部重试或并发配置变化仍可能使部分预测使用原上限；下游实测制动检查继续必要。底盘实际速度也可能因执行器比例误差超过命令，不能用命令限幅替代真机验证。

Humble 平滑器在加速度限制后应用 deadband，会在刹车尾段跳变。配置将 deadband 设为零，由已有持续停稳判据确认到达。

路径跟踪预处理只保存 `setPlan` 输入的 KDL 位姿表示。每周期仍读取新鲜 TF、变换并评分全部路径点，保持原有最近点 / 朝向评分、平分时保留首点、0.20 m 离轨拒绝及速度相关前视距离。新路径完整替换预处理状态；不缓存局部目标、碰撞结论或输入时效。Humble 的 KDL 变换与四元数还原顺序保持一致，不使用平面近似或局部搜索窗口代替原计算。

## 目标、接管与路径恢复

Nav2 保留规划、控制、BT 导航和速度平滑四个服务节点，不启动 `behavior_server`，不自动后退、Wait 或无条件清空 costmap。原有周期规划与控制算法继续使用。

控制失败后，`PathNeedsReplan` 只接受 `/is_path_valid` 对当前仍在使用的路径返回的明确 `is_valid=false`。服务不可用、响应超时、异常、路径已改变或返回有效均不构成恢复证据。只有随后规划成功、替代路径结构有效且与旧路径几何不同，`AcceptChangedPath` 才接受替换并允许一次控制重试；原样路径、只更新时间戳或相反四元数符号不算新路径。证据未知或替代条件不满足时，该恢复终止。

`RestartOnGoalUpdate` 在目标更新时 halt 旧执行子树，清理尚未完成的路径服务请求、规划 / 控制动作及恢复次数，随后按新目标重新开始。旧响应不能继续为新目标提供恢复依据。

手动接管只在速度仲裁层覆盖导航，不暂停 Nav2 的进度检查，也不保存或重放已经失败的目标。输入结束后，新的导航速度仅能来自仍在运行的 Action。完整流程与边界见 [运行机制](runtime-mechanisms.md)。

## 规划与缓存

`PreciseLattice` 的直接连接与新拼接部分只有在整个填充足迹扫掠经过零代价格时才可使用。出现软代价时调用原生搜索，避免几何捷径绕过代价优化。改变 XY 或添加连接的捷径继续遵守零代价扫掠要求。只改朝向、保留相同有序 XY 的有限朝向候选另用完整硬碰撞检查，并在共享细分样本上比较整数软代价 Q：硬检查通过且 Q 不增加才可采用，否则保留原生路径。两类规则不能混为“所有朝向修改必须零代价”。

路径缓存匹配完整代价地图、地图几何、足迹、参数版本与准确目标；软代价增加或减少都会失效。边界检查使用实际旋转多边形与 2 mm 余量。无效或出图端点在调用原生搜索前拒绝。搜索期间锁定地图；当前使用固定 CAD 足迹，Humble 的并发动态足迹更新另有锁边界，外部如要改足迹需与规划串行。

Humble 的 SMAC 库共享静态对象存在两个兼容性风险：同时链接三种 planner 库可在进程退出时重复析构；原生障碍启发式表在地图缩小时存在旧长度填充问题。生产目标只链接 lattice 库，并要求 `cache_obstacle_heuristic: false`；原生搜索前清空该表。插件自己的路径缓存仍可工作。地图快照与完整搜索有成本；已有指定 Jetson 夹具的函数诊断，但当前修正候选的完整长路线性能对照尚未完成，见 [实时性记录](navigation-latency-optimization.md)。

部分 Humble lattice 动态代价参数还有上游限制：即便 ROS 接受新值且缓存失效，运动表在 primitive 文件路径未变时可能保留旧权重。调整此类参数后需重启规划器；本轮没有宣称修复所有原生动态调参行为。

规划预算从 `createPlan` 入口覆盖搜索、后处理查询和返回前检查；检查是协作式截止，不能抢占已经进入的原生搜索调用。显式有限正值预算按配置执行，不再硬截成 15 s；默认 YAML 的 15 s 不因此改成测试使用的 60 s。

## 扫描故障、定位与地图

`VelocityGuard` 拒绝全 NaN、负无穷、错误几何等扫描，收到无效扫描立即输出零并闭锁。合法的正无穷无返回仍受支持。故障后仅时间戳严格更新的合法观测可恢复；重复或回退的时间戳不能延长扫描有效期。此前观察到的近障碍仍由正向空闲证据清除。

固定图启动只保留一个新鲜扫描候选，等待该扫描时间的精确 scan → odom TF，并要求新鲜 map → base_footprint TF；候选仍有效时不被后续扫描不断替换，没有多帧质量等待窗口。固定地图导航持续报告扫描一致性，但质量评分不再控制速度。初值、AMCL 原生恢复和地图语义见 [定位质量诊断](localization-health.md)，必要的停车条件见 [停车保护](safety.md)。地图对称性、动态遮挡和地图缺失仍会限制诊断能力。

guard 的点索引对紧凑分布使用连续桶偏移与原始点索引，上限为 65,536 个格及 `16 × max(64, 点数)`，超限回退原哈希桶。部分点的包围范围只用于提前证明超限；启用连续存储前仍检查全部点。查询保持原桶遍历顺序、桶内原始顺序、点半径及精确距离判据，不删除内部占据格，也不扩大查询裁剪。索引只在点集更新时重建；制动检查、安全周期与输入时效不变。

SLAM Toolbox 的 Ceres 固定节点使用稳定 ID，并正确清理被删除节点的约束；哈希表扩容、删点重加和孤立节点重新连接有实际求解器回归检查。

新保存地图明确使用 PGM/trinary、`free_thresh: 0.196` 与 `occupied_thresh: 0.65`，避免未知像素 205 重新加载成空闲。客户端在发布快照前检查实际保存的像素和阈值，拒绝不完整或错误快照。它不拿异步 `dynamic_map` 去覆盖后续 SaveMap 的原点。旧地图不自动迁移；Nav2 保存 YAML 的三位精度仍可能量化任意原点，本轮未修复这一上游问题。

导出共用一个 `save_timeout` 客户端等待预算，覆盖快照锁、地图服务、位姿图序列化与运行时参数查询；后端保存回调不再固定等待一秒。运行时参数元信息缺失只记录警告，不丢弃已经有效、完整的栅格图与位姿图。像素、阈值、文件完整性与原子发布检查继续保留。该预算不能抢占服务器内部处理，在线各次服务调用也不保证严格同一时刻的快照。

## 复现检查

构建开关、独立 CMake / CTest、隔离探针和组件计时统一见 [导航验证与性能复现](navigation-validation.md)。默认硬件构建关闭 `BUILD_TESTING`，不能直接假设该目录已有 CTest。`validate_hardware.sh` 检查 Python 和 launch 参数，不能替代导航算法回归。

本页描述开发工作树契约，不代表已合并 main 或完成真机验收。桌面 API、合成输入、冻结录制回放与真实行驶分别报告；当前检查不等于 N10Plus 实测、Orin 性能或毫米级真机精度保证。
