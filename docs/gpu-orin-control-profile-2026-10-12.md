# Orin 控制周期定位（2026-10-12）

当前新 CUDA 模式的主要持续开销是 GPU 栅格足迹/轨迹代价内核，狭窄场景的超时长尾主要出现在局部 costmap 锁等待。该结论来自独立计时副本，生产算法、40 ms 预算和默认部署未修改。

完成四个场景的 12 场原二进制/计时版配对试验，以及 4 场关闭 CUDA 设备事件计时的补充 ABBA 对照。Gazebo 在电脑，导航在 Orin；只测试显式 FollowPath，没有实体驱动、全局重规划并发或 RViz 压力。128 条候选、56 步、4 支撑点及原速度/足迹/制动边界保留。计时与低开销版的相关数学/几何检查均为 6/6，公共 API 输出与原版逐元素一致。

## 分段结果

以下为主计时版噪声种子 21；单位 ms。全部调用包含 CPU 快速路径和停靠，进入采样分支的周期另列。

| 场景 | 全部调用均值 / P95 | 采样分支完整调用均值 / P95 | 主要开销 |
| --- | --- | --- | --- |
| 开阔直线 | 0.331 / 0.645 | 无 CUDA 采样 | 原 CPU 快速路径 |
| 开阔转弯 | 7.234 / 13.912 | 13.733 / 21.884 | GPU 工作；偶发 TF 等待约 31 ms |
| 60 cm 转角 | 16.281 / 32.471 | 27.898 / 35.348 | GPU 代价核、地图锁及部分 CPU 直连扫掠 |
| 50 cm 转角 | 28.118 / 44.061 | 28.118 / 44.061 | GPU 固定开销叠加地图锁等待 |

GPU 设备事件显示：开阔转弯的 rollout / cost / reduce 均值为 4.065 / 6.322 / .116 ms；60 cm 为 4.070 / 17.699 / .132 ms；50 cm 为 4.122 / 16.066 / .097 ms。cost 内核包含完整栅格足迹/轨迹扫掠和代价，未再拆分内部 helper。CUDA 事件时间与主线程等待重叠，不能直接相加。

关闭设备事件计时后，两次 50 cm 的实际预算拒绝周期，锁等待均值仍为 19.093 / 19.219 ms，CUDA 完成等待为 21.342 / 21.258 ms，最终 CPU 制动为 .276 / .269 ms。一次完整调用 61.577 ms，其中锁等待 36.798 ms、CUDA 等待 20.162 ms。主要等待点在 snapshot 的 crop 地图取锁；调用线程在此的 CPU 时间通常只有几微秒。

局部地图为 4×4 m、1 cm（160000 格），15 Hz 更新，包含 static/obstacle/inflation 层。尚未逐层计时更新线程，不能把全部持锁工作归到某一层。60 cm 的 CPU directApproachClear 均值 4.124 ms、最大 30.670 ms，属于另一处可优化查询。实际执行 checked 的周期均值约 .05–.63 ms，目前不支持优先削弱制动检查。

插件返回到实际 /cmd_vel_nav 发布的平均间隔约 .16–.27 ms，原版 rcl_publish 均值约 .08–.19 ms，不是上述十几毫秒的主要来源；这不等同一程网络时延。进入插件前的取位姿和循环睡眠尚未逐函数拆分。

## 计时影响与推进质量

主矩阵的 50 cm seed21 超时计数为计时版 91、原版 8；补充 ABBA 为原版 17/93、低开销版 28/39，存在明显运行相位与观察影响，不能把计时版频率当作原版的固定超时率。关闭事件后保留了锁等待叠加 GPU 等待的组成证据。

50 cm 的失败还包含可行候选不足。主计时 seed21 的 800 周期中仅 228 次有合法序列，35 次合法结果随后被预算拒绝，193 次返回非零指令，其余 572 次没有合法序列。仅优化耗时不能据此宣称解决转角。status=0 的窗口记录没有确定 Action 终态，取消请求被接受但不冒充到达或终态取消完成。16 场均无独立平面完整足迹碰撞，所有自有进程组和临时容器已停止；首场元数据引用失败前缀保留。

后续优先定位地图更新线程的持锁工作、优化 GPU cost 内核，再减少重复 TF 查询和 CPU 直连扫掠；保持制动边界，并单独处理候选可行性。生产代码尚未应用这些优化，独立计时源码/二进制和原部署均通过结束后的哈希及状态核验。
