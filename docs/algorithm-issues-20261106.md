# 当前算法问题清单

更新时间：2026-11-06。以下区分实测现象、历史失败和尚未完成的验收；并非所有项目都已查明根因或证明属于当前版本的代码错误。未改变定位、建图或控制算法。

## 1. 导航几何：特定场景耗时回退（已观测，原因未定位）

同机固定合成输入下，密集障碍直行的完整控制调用，新版中位数 0.469–0.475 ms，原版 0.235 ms。空旷场景也慢约 0.016 ms；窄道居中则接近或略快。重复两次只是观察，不是统计置信区间。整个控制器改动不止几何计算，不能把差异直接归到某个 kernel、阈值或诊断。

当前默认 `gpu_minimum_work` 的调度和控制器分支决定实际设备。强制 GPU 时，本次密集直行降到约 0.160 ms，但窄道上升到约 1.21 ms；日志批次数是所有场景汇总，无法据此确定每个场景的实际设备分支。下一步应对相同固定输入按场景单独测量几何、传输/同步、边界复查及其他控制开销，同时核对输出；确认主要成本后才选择优化。不要统一强制 GPU。

证据：[新旧组件配对报告](../output/paired-gpu-20261105/report.md)。

## 2. MPPI 行为与实际闭环效果（尚未验收）

采样场景中两版输出存在差异：本次最大 `vx` 约 0.061 m/s、`vy` 约 0.037 m/s、角速度约 0.049 rad/s。优化器和随机数实现不同；单次控制命令不同既不证明错误，也不证明导航质量相同。六个非采样固定场景的本次输出一致。

后续应在相同地图、起点、目标、障碍、传感器输入及控制链条件下，记录完成率、碰撞/净距、到点偏差、耗时与时延；保留各自随机种子并多次重复，先验证测量与执行链。现有组件测试和单机计时不能代表实车表现。

## 3. 全局重定位与跟踪精度（历史失败，当前默认关闭实验捕获）

项目配置 `global_acquisition_enabled: false`。2026-11-06 增加人工粗略起点附近的有限区域自动搜索，独立于全图初始化开关；其数据与验收范围见 [局部初始化说明](local-initialization.md)。历史旧路径在一个 LILocBench 全局查询上失败；一个较早实验实现也曾在重复结构查询中误捕获。后续 A02 和 FAST 修订在指定数据上有改善，但并未完成广泛场景泛化验证，不能把早期实验失败简单断言为当前默认跟踪路径的现行故障。

历史 FAST 的一次 2 倍速误差回归中，LT-D0 最大位置误差约 0.605 m，LT-D1 约 0.484 m；该实验使用固定训练坐标和特定数据/配置，不是当前整机或 10 Hz 雷达的实测。协方差小、离散格点证书或首次输出都不等于真实位姿准确。下一步需保留地图及坐标注册约束，以未参与设计的数据、明确初始条件和独立真值分别评价误捕、首次有效输出、持续跟踪误差和恢复能力；实验捕获保持显式启用。

另有明确的兼容路径限制：普通 PF 跟踪尚未强制按来源去重，重复或乱序扫描可能仍被消费；诊断的时间高水位不会把这些旧数据当作新鲜观测，但这不等于 PF 没有使用它们。应先通过真实录包确认帧身份、时间戳及重复/乱序是否出现，再设计兼容的拒绝策略，当前不能据此断言雷达存在重复帧。

证据：[AMCL 实现与历史边界](realtime-goal-amcl.md)、[FAST 回归报告](../output/lilocbench-fast-init-precision-20261020-A01/report.md)。

## 4. 当前建图链（缺少对应版本的真实节奏验收）

当前源码包含扫描时间、几何与 SLAM 后端补丁，但尚无当前版本完整建图→定位→导航的真实雷达验收。配置中的扫描运动补偿默认关闭，扫描头时间采用首束假设；这不是已校准的雷达采样时序，应先核实驱动实际时间语义与运动、TF 数据，再决定是否启用补偿。现有约 10 Hz LILocBench 回放使用历史后端，原始数据由 15 Hz 抽帧，间隔 61.88–137.40 ms，不能当成当前源码或真实 10 Hz 雷达验证。下一步使用用户雷达原始 10 Hz 录包，保留源时间、里程计和 TF，以建图输入、建图输出和可用外部参考分别核对；无独立真值时不要声称地图精度。

此前人工 20 Hz 在线建图压测及针对该压测的修复按用户要求继续暂停；目前没有证据确定其历史缺帧的具体环节。

证据：[约 10 Hz 数据说明](../output/lilocbench-10hz-20261105/README.md)、[工作区状态](current-workspace-status.md)。

## 5. 实验性建图模型和厘米级任务（未完成）

连续几何、子地图和共享证据属于影子/实验实现，不应假定已用于生产或已提高精度。现有目标记录是被动观测，RViz `/goal_pose` 和直接 Action 请求的来源覆盖不同，里程计及控制器状态不等于独立物理真值。2 cm / 1° 与 95% 联合到达率均未在真实平台验证；需先有独立工作点真值、外参、执行器和时间基准，不能仅依赖估计位姿或调小控制容差。

证据：[任务来源与评价](realtime-goal-navigation.md)、[影子建图范围](realtime-goal-mapping.md)。
