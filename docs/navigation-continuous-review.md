# 较快的单终点长程导航

2026-10-07，硬件算法提交 main `c621f9c`，同步至 sim。目标设备仍为 Orin Nano 8GB、JetPack 6.2、N10Plus 二维雷达，无相机；当前结果来自本机 x86 运动学仿真。

取消窄道统一 **0.10 m/s** 限速，窄处上限现为 **0.50 m/s**。同一实际雷达地图、种子 44 和带误差的速度输入下，单终点整程由 **315.423 s 缩短至 115.869 s**，约快 **2.72 倍**，两者均无碰撞。上限并非全程速度：侧移、倒车、转弯、制动空间和末端停车仍会降速。

当前 GUI 使用在线 SLAM，复用此前雷达实际采集的图；每次只发送一个整程 `NavigateToPose` 终点，到达之后才发送返程终点。场景中的中心线用于构造、验证地图，不输入导航。此测试验证已观察地图上的长程导航，不能证明机器人能自主探索完全未见过的复杂迷宫。

## 算法修改

- `FollowPath.narrow_speed_max: 0.5` 替代源码中的固定 0.10 上限。小幅窄处对齐、居中、末端收敛、实际速度与请求/过渡速度的制动扫掠、独立 guard 和 Collision Monitor 保留。
- 全向底盘遇到大幅前视转角时，优先尝试经填充足迹检查的保持朝向平移，避免在前一段窄直道中过早旋转。普通小角度对齐仍保留。
- 全局路径删除重叠 lattice primitive 中重复的 SE2 回路，同一位置的不同朝向仍保留；任何新连接继续完整验证。
- 若整条原生 Smac 路径保持初始底盘朝向，连同最终精确旋转都可通行，则采用该经过验证的朝向方案。没有使用场景预设路线替换规划器。
- 每次重规划索引当前地图中的占据单元。缓存路径仅在目标相同、机器人接近路径且**整条剩余路径及新起点连接都通过当前地图检查**时复用。新增障碍导致检查失败即重新搜索。
- 初次大地图搜索预算由 2 s 调至最多 15 s，并启用原生障碍启发式缓存。测试中初次搜索仍有数秒等待，后续沿路继续重规划；没有把中间位置变成新的用户目标。

## 真实运动与验收

地图中心线长 30.4 m，8 个直角弯，常规通道宽 60 cm，4 处缩窄至 54 cm；占据区域填满通道之外空间，无法绕过。实际路径会在安全范围内圆滑过弯，长度约 29.2–29.6 m。碰撞评价沿用底盘含四轮投影，并以不大于 4 mm 的平移/角部行程插值检查真实几何交集。

输入保留 5 mm 雷达噪声、3% 轮速尺度误差、0.003 m/s 速度噪声及 0.001 rad/s 陀螺偏置。种子控制适配器扰动，Gazebo 雷达噪声流未固定。真值仅用于独立评价及原有合成速度传感器；EKF 忽略 `/odom` 中的位姿字段，未将完整真值位姿用于定位融合或导航控制。

严格验收仍为真实终点位置 ≤20 mm、朝向误差 ≤0.035 rad、末速 ≤0.020 m/s，且 Action 成功、无碰撞。Action 成功与严格验收分别记录。

实际雷达图在修正下述仿真角速度问题前采集，因此会继承旧图误差。低速版本也未通过 2 cm 要求，不能把全部位置误差归因于提速；当前证据也不能把残差单独归因于某一个 SLAM 参数。固定地图试验明确使用场景几何生成的已知地图及 AMCL，初始位置有随机误差，不作为在线未知环境的证据。

额外回归包含已知/在线 50 cm 门、薄障碍、动态横穿、雷达中断和在线薄障碍，各种子 50、51：**12/12 严格到达，2/2 故意危险高速指令安全停车，0 次碰撞**。导航最大终点误差 9.3 mm。该批次在仿真发布器修正前完成，使用同一 main 算法，均为小角度运动。修正后另外完成整圈传感器验证及上表全长导航。

Release C++ 检查 3/3、硬件 Python/键盘测试 52/52、仿真场景测试 5/5、lattice/在线配置检查 10/10 通过。初次宿主 Python 和未安装驱动的部分环境测试失败记录保留，补齐正确 ROS 环境及硬件驱动构建后通过，没有删减检查。

## 仿真角速度问题与保留的失败

初次直接长程测试中，旧 main 和仅释放速度的候选均因原生搜索预算不足失败；两次失败记录保留。增加搜索预算后的诊断演示也出现弯口安全停车，推动了上述路径/朝向修改。

第一轮较快全程虽然 Action 成功且没有碰撞，最终真实朝向偏差达约 92°，严格验收失败。进一步比较原始里程计、适配器里程计、IMU 与 EKF，复现了 Gazebo Sim **8.12.0** 的四元数符号变化问题：真实约 0.45 rad/s 的转动触发一次 **627.8 rad/s** 里程计脉冲，EKF 随之跳变。该失败及未修正的低速全程均完整保留。

在仿真专用库中回移上游的四元数同半球修正，保持硬件 EKF、SLAM 后端和噪声输入不变。正反向各 16 s 的整圈传感器测试中，修正前有 1 次原始里程计脉冲和 3 次 EKF 异常角速度，修正后均为 0，最大角速度约 0.4501 rad/s。当前 GUI 进程已实际加载该私有库，二进制 SHA-256 与试验一致。

来源：[8.12.0 原始发布器](https://github.com/gazebosim/gz-sim/blob/gz-sim8_8.12.0/src/systems/odometry_publisher/OdometryPublisher.cc)、[上游修正](https://github.com/gazebosim/gz-sim/blob/gz-sim8/src/systems/odometry_publisher/OdometryPublisher.cc)。仿真保留原始 Apache-2.0 版权头及来源说明。系统安装包和 main 的硬件实现未因此更改。

## 交付与复现

main → sim 的 62 个算法/配置文件逐字节一致，原检查点的 86 个 CAD/描述文件 SHA-256 保持一致。完整结果、轨迹、命令链、失败、源代码快照、实际采集 SLAM 图及插件证据位于 `docs/evidence/navigation-continuous/`。旧 [v7 窄门结果](navigation-narrow-review.md) 仅代表其原冻结版本，不能直接作为当前提速版本的测试数量。

在 sim checkout 使用独立输出、域及 Gazebo partition 重跑：

```bash
tar -xzf docs/evidence/navigation-continuous/navigation-continuous.tar.gz -C .cache
DUOJIN_NAV_OUTPUT="$PWD/.cache/continuous-reproduce" \
  DUOJIN_NAV_CONTAINER=duojin02-continuous-reproduce \
  DUOJIN_SIM_DOMAIN=93 DUOJIN_SIM_PARTITION=continuous_reproduce \
  simulation/navigation_benchmark.sh --cases winding --seeds 44 45 \
  --variants upgraded --scenario-file /ws/simulation/scenarios/long_winding.json \
  --slam-graph /ws/.cache/navigation-continuous/winding-scanned
```

当前 GUI 的 `mapping:=true`，仍使用 pinned SLAM Toolbox，无 AMCL/map server；演示脚本为 `simulation/live_navigation_demo.py --scenario /ws/simulation/scenarios/long_winding.json`。每个来回只提交两个目标。

Orin 当前不可访问。本轮没有证明真实轮速、真实刹车、麦轮打滑或 Orin 控制时限；保留 0.50 m/s 上限及所有制动保护，真机接入后继续测量与标定。当前已知地图长程严格验收 2/2，在线实际雷达图长程尚未满足 2 cm 位置要求，不能承诺现实常规场景绝对 100% 到达与精度。
