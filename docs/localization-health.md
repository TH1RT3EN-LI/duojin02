# 固定图定位健康与恢复

本页集中维护固定图的状态机、扫描 / 地图语义与恢复操作；模块和话题所有权见 [开发接口](../README_DEVELOPMENT.md)，验证层级见 [优化状态](navigation-optimization.md)。配置阈值见 [localization_health.yaml](../src/duojin01_bringup/config/localization_health.yaml)；本文的窗口与参数描述不能当作已经完成实物标定。

`nav2.launch.py` 在 AMCL/map server 之外常驻启动一个 `localization_manager`，同时负责健康判断、恢复和导航命令许可。它按扫描实际时间查询 `map → laser`，核对有限返回端点与占据格、用逐格 DDA 检查返回之前的射线是否穿过墙体。协方差小、TF 新鲜都不单独构成通过条件。

## 先看状态与原因

`/localization/status` 的 `state` 与 `reason` 解释为什么放行或闭锁；`recovery_phase` 是恢复子阶段，不能当作另一个健康状态。

| `state` | 导航定位资格 | 下一步 |
| --- | --- | --- |
| `WAITING` | 未取得 | 检查地图、扫描、精确时间 TF 和真实初值，等待确认窗口 |
| `SUSPECT` | 已撤销 / 尚未取得 | 检查几何失配；启动阶段可等收敛，曾健康后连续失配会锁定 |
| `HEALTHY` | 已取得 | 命令仍经过新鲜度、仲裁及 VelocityGuard 检查 |
| `PERCEPTION_STALE` | 已撤销 | 修复扫描 / 精确时间 TF，重新积累常规确认窗口 |
| `MISMATCH` | 硬闭锁 | 修复原因后明确恢复或提供真实人工初值；新扫描不能直接解除 |
| `RECOVERING` | 闭锁 | 等服务和新观测验证，服务受理不等于成功 |
| `RECOVERY_FAILED` | 硬闭锁 | 查看失败原因，修复后明确重试 |

## 确认窗口与时效

启动需至少 6 个不同时间戳的有效扫描，跨度 0.5 秒；偏差初值可等待收敛。曾健康后第一帧失配即撤销许可，连续 3 帧、跨度 0.2 秒锁定 `MISMATCH`。格式错误、收到即过期 / 非法时间戳、源时间回退及地图更改也硬闭锁。

纯扫描缺失或精确时间 TF 等待超时会立即撤销健康许可。已健康的节点进入 `PERCEPTION_STALE`，恢复后重新取得至少 6 个不同时间戳、跨度 0.5 秒的连续有效扫描，才可自动放行；重复时间戳不刷新有效期，多次中断不能拼接确认窗口。启动阶段的中断只清空窗口，不强制全局重定位。已存在的 `MISMATCH` 或 `RECOVERY_FAILED` 不会因中断或正常扫描自动解除。正在 `RECOVERING` 时，中断清空扫描与位姿确认窗口，但不延长服务或验证截止时间。

确认同时要求最低帧数和整段连续源时间跨度；帧率高于 10 Hz 时需更多帧覆盖相同时间，不降低时间门槛。好坏观测互换、中断、故障和明确恢复都会重新开始对应窗口。即使最后一帧刚好满足证据要求，评分结束已超过恢复截止时间仍按超时处理，不能放行。

定位管理器在同一状态机内撤销导航许可，无需经 JSON 健康消息再传给第二个进程。扫描和命令使用 steady timer 检查有效期；ROS 仿真时钟暂停仍会停车，继续仿真后需新的扫描窗口。管理器退出时，VelocityGuard 和串口驱动各自的命令超时负责停止底盘。时钟回退属于硬故障，可能需要重启相关节点以建立新的时间会话，不能把保留的旧时间戳作为恢复证据。

## 扫描证据与缺测语义

默认从 540 束选择 90 个均匀方向，再按观测有效性判断，不能用其他方向补足删去的束。需至少 45 个有限命中，端点匹配比例 ≥ 0.75、有限观测在已知地图中的支持 ≥ 0.90，有效有限回波的射线穿过已知墙体的矛盾比例 ≤ 0.15。当前 N10 驱动先过滤小于最小距离和大于最大距离的点，再把所有空角度格初始化为 `+Inf`。因此同一值包含近回波被删去、缺角度数据及远处无返回，不能证明后方自由空间。`+Inf` 和超出扫描声明 `range_max` 的有限值均不提供正负几何证据，也不进入矛盾分母。整帧无返回或不足 45 个命中仍拒绝健康资格。

有效有限回波仍检查近处及远处墙体，并沿用端点之前 0.18 米的射线余量。超过策略计算范围 8 米、仍在传感器声明范围内的有限返回保留截断范围内的射线矛盾及比较分母，只不提供范围之外的端点支持。激光原点落在占据格会拒绝整帧。近射线和后方射线计入同一逐格工作预算，浮点停滞也不能绕过预算。状态证据的 `unobserved`、`policy_clipped`、`compared`、`contradictions` 和 `ray_work` 区分缺测、策略截断和实际比较量。

未知和中间占据概率不提供已知支持。`NaN`、`-Inf` 和低于 `range_min` 的范围会拒绝整帧，包括未选入 90 束的方向。阈值在上方链接的 `localization_health.yaml` 中；它们是保守初值，不是 N10Plus 真机标定的最优值。大面积遮挡、动态障碍、地图不完整和少量非返回都可能造成停车，状态消息提供原因与分母。

这项规则限定于当前发布链路。[LaserScan 消息](https://raw.githubusercontent.com/ros2/common_interfaces/humble/sensor_msgs/msg/LaserScan.msg)要求丢弃距离范围之外的数据；[REP117](https://raw.githubusercontent.com/ros-infrastructure/rep/master/rep-0117.rst)另有过近、无效和无返回的编码约定。遵守该约定、提供明确无回波/自由空间语义的传感器可能采用不同模型，不能把本规则推广为所有雷达的唯一处理方式。配置中的 AMCL likelihood-field 模型忽略最大距离返回，Nav2 costmap 的 `inf_is_valid` 保持 false；这次缺测语义修正保持驱动、costmap 与制动 guard 的策略；后续计算优化的状态单列于实时性记录。

## 导航许可与观察话题

`/localization/status` 的 JSON 带源产生时间、扫描时间、递增序号和启动会话；启动就绪检查这些元数据，保留的旧 `true` 不能解锁。`/localization/healthy` 的 Bool 只供观察，管理器直接使用自己的评分状态，不解析自己的 JSON。

管理器只接固定图 Nav2 的 `/nav/localization_requested`，放行后输出 `/cmd_vel`；完整指令链和在线 / 遥控接口见开发接口。闲置时不续租 mux；请求过期发最后零帧后停止续租。健康恢复后需新发布的请求，闭锁期间或健康失联前排队的 DDS 请求不能重放。

## 操作恢复

先观察状态，再明确请求全局重定位：

```bash
ros2 topic echo /localization/status
ros2 service call /localization/recover std_srvs/srv/Trigger '{}'
```

服务 `success: true` 表示受理。管理器调用 AMCL 的 `/reinitialize_global_localization`，最多 2 次；每次等服务最多 2 秒、等响应最多 3 秒、验证扫描最多 8 秒。恢复期间允许调用 `/request_nomotion_update`，以每 0.35 秒最多一次的速度请求停车时的测量更新，不会命令机器人移动。失败保留 `RECOVERY_FAILED`，导航继续闭锁。初始服务失败原因保存在状态流；后续坏扫描可能更新当前 `reason`，但不会解除失败状态。重复服务调用不会建立并行恢复。

导航仍在发送有效请求时，管理器维持 mux 的导航优先级；若要使用遥控初始化位置，先取消导航目标。恢复确认后会放行当前导航目标产生的新请求。

也可以在 RViz 发送新的 `2D Pose Estimate`。已有闭锁会进入单次人工初值验证。两种入口都需至少 15 个源时间晚于恢复响应/人工初始化的扫描，跨度 1.4 秒，并且至少 3 个源时间晚于同一边界、与已评分扫描关联的新 AMCL 位姿观测，才允许恢复导航。响应前的扫描即使响应后才到达或才取得精确 TF，也不能启动或增加恢复确认窗口。重复扫描时间戳、循环轮询 TF、排队的旧位姿都不能充当确认。节点不读取真值，不会自动因为扫描失配发起全局服务。

## 地图契约与局限

当前固定图 AMCL 使用显式 `amcl_nearest` 查询语义：pinned Karto/SLAM Toolbox 和 AMCL 把保存的 origin 对应到第一个格中心，索引为 `floor((p-origin)/resolution + 0.5)`。管理器不会移动原点或位姿。`occupancy_cell` 可明确选择标准 floor/格中心偏半格的后端语义；它不作为现有 AMCL 路线的默认修正。Pinned AMCL 忽略地图 origin 的 yaw，因此本路径拒绝旋转地图。只把占据值 0/100 当已知，其他值当未知，和 AMCL `convertMap` 一致。

地图几何一致性无法证明重复走廊等完全相同观测区域中的全局身份。多帧确认仍有这个边界。需要人工已知初值或额外全局候选/唯一性约束；本模块不能宣称解决全部绑架、回环与全局定位问题。

当前核对把整帧射线放在 LaserScan 的 header 时间，没有逐束运动补偿；运动扫描的误拒风险还需要 N10Plus 时间标定与 deskew 验证。

历史缺测规则与会话证据保留在 [定位评审历史](localization-health-history.md)。测试方法见 [导航验证](navigation-validation.md)；桌面回放的停车输出不会改变预录轨迹，不能证明实际恢复、Orin 用时或车辆制动距离。
