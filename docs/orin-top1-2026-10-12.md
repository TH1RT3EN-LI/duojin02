# Orin Top1 导航入口

用户于2026-10-12选择采用这套配置。入口为 `scripts/navigation_top1.sh`，参数文件为 `src/duojin01_bringup/config/nav2_orin_top1.yaml`，独立安装为 `install/orin_top1`。常规入口和原 `nav2.yaml` 保留。

| 部分 | 已选择的运行配置 |
|---|---|
| 控制与模型 | 20 Hz，model_dt0.05 s，56步 |
| local costmap | 更新10 Hz，发布上限20 Hz，实测消息接收约10 Hz |
| GPU采样 | cuda，128候选，4支撑点，path_primitives |
| GPU执行 | interval核，rollout/cost线程32/32，OMP4 |
| CPU几何 | compute_backend=cpu，最终制动与独立guard保持 |
| 优化 | 精确EDT inflation、周期TF缓存、按需同周期地图快照、CPU扫掠索引 |
| 平移速度（2026-10-13） | 前后、左右各单轴 ±0.5 m/s；斜向无新增全局合成速度限幅 |

`gpu_batch_size=128`是GPU独立搜索规模；原CPU `batch_size=1600`保持。2026-10-12 采用时保留原速度上限；2026-10-13 按用户选择统一平移单轴上限为 0.5 m/s，并同步 controller 与 velocity_smoother。加速度、footprint、padding、unknown/障碍记忆、制动、定位门控及 goal checker 保持。地图发布上限20不等于独立20 Hz地图发布器。最新配置与试验范围见 [速度收尾记录](chassis/speed-envelope-2026-10-13.md)。

启动使用该独立入口；地图仍由原工程的map路径解析和lattice分辨率匹配处理：

```bash
cd /home/dj/duojin02-gpu
./scripts/navigation_top1.sh map:=/absolute/path/to/map.yaml
```

该命令会启动实体硬件导航。仅查看launch参数使用 `./scripts/navigation_top1.sh --show-args`，不会启动实体驱动。当前部署验证只进行了原生检查与隔离domain的inactive controller配置，未执行实体运动。

也可以先 `source ./source_top1.sh`，再用原launch明确传入 `params_file:="$PWD/src/duojin01_bringup/config/nav2_orin_top1.yaml"`。独立入口固定这份参数文件，拒绝再次传入params_file覆盖；使用不同profile应明确走相应入口。

`docs/evidence/orin-top1/release.json`锁定已测原生v4库、plugin注册和参数文件SHA。启动前必须通过 `python3 scripts/verify_orin_top1.py`：aarch64、所有required文件和profile均正确，才加载该overlay并设置线程/内核环境。来源为保存的v4安装归档及其最终版本build manifest；没有把桌面二进制拷到Jetson，也没有重新构建来替代已测库。普通hardware构建不会重建这个独立发布目录；若需要更新算法或重新编译，应从冻结源码构建并重新验证、更新发布manifest。

Top1采样后端明确为cuda。无设备/不兼容配置应拒绝配置，运行时GPU错误或超预算会停止，不应当作CPU无缝接管。恢复时重新配置生命周期并核对设备状态。40 ms预算仍是软预算，不能中断任意驱动阻塞。

最新定位见[底盘因果筛查](/home/th1rt3en/Documents/Codex/2026-10-13/outputs/chassis-causal-screen-20261013/report.md)。以下记录保留2026-10-12的问题背景；后续进度按新的底盘范围与0.60 m门槛判定：

1. **50 cm转角任务仍未解决。** 更新10/15/20 Hz三档都0/6到达，无合法候选周期约55%–58%。现有记录不足以区分几何可行性、候选覆盖、序列选择、CPU制动接受和下游执行。下一项优先保存失败周期的同版本map/footprint/pose/实测速度/path、候选与选中序列、最终制动结果及逐级命令接收。
2. **长尾尚未消除。** 10 Hz主组仍有2/8008次超过40 ms、最大42.85 ms。发布cap20的静态8场未超预算，但动态阻挡压力场景平均调用11.08→12.28 ms、地图等待0.215→1.472 ms。旧独立诊断中StaticLayer costs仍约4.93 ms，内部TF、重映射与CPU尚未拆分；它是后续性能优化点。
3. **动态绕行与真实响应尚未证明。** 动态测试箱体占住目标及其2 cm容差，是阻挡停车/拒绝压力试验。82.47 ms是旁观发布戳年龄代理，未记录controller/guard实际消费的观测源版本。线速低速dwell也不等于线/角速度都停稳。
4. **外形与足迹覆盖有边界。** 本配置只验证固定八边底盘footprint。当前工程未建立机械臂关节到导航/guard动态足迹的联动，伸出机械臂或外挂后全机外形没有本轮碰撞证据。单快照分支的动态footprint并发契约也未验证。
5. **完整任务链和实体长期运行属于验证缺口。** 本轮主测试是固定路径FollowPath，不能据此继承NavToPose全局规划/重规划的质量结论。真雷达/里程计、实体制动、冷启动和持续热负载没有本轮完整闭环证据；不把这些缺口记成已发现故障。
