## 地图先验只查询可能影响完整制动的区域

`guard_query.hpp` 的保守查询半径包含足迹最大顶点半径、平移制动距离、离散推进误差、额外余量、扫掠插值误差、占用格子的外接半径和定位不确定性。对于实测速度和请求速度，取较大的平移速度模长 V；所有缩放请求和实测到请求的凸组合速度都不超过 V。

制动推进先积分再减速，因此平移距离使用 `V*(reaction+0.04)+V²/(2*deceleration)`。0.04s 覆盖两个最大20ms离散步，插值余量覆盖现有4mm空间步的一半；旋转期间整个足迹始终在外接圆内。查询仍以原来的2.5m记忆范围为上限，保留原先的范围语义，并包括每个先验格子的半径及定位余量。原来的四组制动与速度过渡检查完整执行。

静态占用格子在地图更新时建立10cm分桶索引；查询时先在地图坐标系裁剪，再转换少量候选格子和做原有观测关联。激光观测索引在接受一帧新扫描后重建，两个安全周期之间复用；地图更新重新建立先验索引。没有把墙体内部删掉、只留轮廓，或减小栅格/碰撞几何的精度。

## 一个指令周期使用一致的局部地图快照

`PreciseMPPI::snapshot()` 在一次持锁期间复制原查询范围的代价字节、原栅格原点、分辨率、裁剪下标和足迹。复制完成即释放代价地图锁，障碍提取与多次 `nearObstacle()` 使用这份快照。新周期重新复制，不缓存旧安全判定。世界坐标转换仍先相对原地图原点求栅格下标，避免裁剪原点改变边界舍入；超出快照时保守地按狭窄区域限速。

这一改动减少重复获取地图锁和持锁期间的逐格计算；第一次获取锁仍可能等待代价地图更新。原生 MPPI 回退路径、速度限制、完整足迹检查及下游实测速度安全门继续使用。

## 扫描 TF 就绪后处理

使用 Humble 的 `tf2_ros::MessageFilter` 缓存最多2帧扫描，TF 等待上限20ms。监听器、就绪回调、订阅回调和安全定时器在同一个单线程执行器中运行，处理回调使用零等待的传感器时间 TF 查询，避免共享安全状态的数据竞争和同步等待。每帧消息仍保留原扫描时间戳；不换成最新 TF。

有效性检查在入队前执行，坏扫描立即停止。就绪后重新检查时间与故障顺序；故障前排队的旧帧无法解除较新的扫描故障。心跳沿用入队收到消息的稳态时刻，TF 等待不会延长扫描有效期。无法获得 TF 的扫描不能刷新心跳，20Hz 安全定时器继续检测指令、里程计、扫描和地图过期。

该机制参考 [ROS 2 Humble 官方 MessageFilter 教程](https://github.com/ros2/ros2_documentation/blob/humble/source/Tutorials/Intermediate/Tf2/Using-Stamped-Datatypes-With-Tf2-Ros-MessageFilter.rst)，并按实际安装的 Humble 头文件编译与测试。

当前规划器要求 `cache_obstacle_heuristic=false`；第一次沿用旧测试启动文件时被其配置检查拒绝，尚未提交导航 Action。该前缀保留在 `startup-failure-1`，后续两组统一使用符合当前源码要求的新测试启动文件。完整结果与原始记录放在本次优化报告中。

Humble 的 `Buffer` 带 timeout 重载即使 timeout=0 也会检查独立监听线程；单执行器方案应明确调用 `BufferCore` 的立即查询接口。初版路线虽完成，但发现该重载让地图记忆锚定检查失败，因此保留为无效候选 `tf-api-warning-1`。新增真实地图修正探针验证保留表面随源时间 TF 平移，同时检查日志没有线程错误；最终性能只采用修正后新启动的候选。

## 2026-10-10 本地继续：只缓存精确相同输入的关联结果

[PriorAssociationCache](../src/duojin02_navigation/include/duojin02_navigation/prior_association_cache.hpp) 以地图 / 观测更新代数、点索引 / 数量、精确变换位表示、定位余量与距离误差作为键；来源变化即失效。查询区域新出现的点首次计算。它只复用“地图点是否已有当前激光关联”，不缓存制动判断或任何输入新鲜度；坐标、半径及完整扫掠仍逐周期计算。20 Hz 安全频率和配置未变。

本机 11 项 CTest 通过；ROS 检查覆盖 15 项扫描故障、4 项 TF 和 9 项缓存场景，其中缓存探针已纳入 CTest；缓存最终探针先验证稳定命中再变更来源，并确认 guard 正常退出。新状态字段 `prior_association_hits` 与 `prior_association_misses` 是最近一次有效障碍构造的计数，故障短路时可能保留旧值，不能作为所有周期的累计工作量。

合成组件串行 ABBA 每次 10000 周期，有重复输入时平均线程 CPU 0.133556→0.078419 ms（−41.3%），关联计算约减半；变换或扫描每周期变化时无命中，平均额外 CPU 为 +0.25% / +1.87%。这些只是 x86 障碍构造组件测量，不涵盖 ROS、制动、完整导航和 Jetson 实时性；不与上文旧板端数据拼成加速比例。

仓库附带 [分项结果](evidence/navigation-association/summary.json) 和 [逐次记录](evidence/navigation-association/records.json)。完整冻结源码、语料、功能探针及短采样前缀另见 [本地报告](/home/th1rt3en/Documents/Codex/2026-10-10/outputs/jetson-association-cache/report.md)，不随仓库分发。

## 2026-10-10 本地后续：路径目标选择预处理

[PathTarget](../src/duojin02_navigation/include/duojin02_navigation/path_target.hpp) 在 `setPlan` 时把不可变的输入转换为 KDL Frame。每周期仍获取原有新鲜 TF，使用 Humble 原计算的 Frame 乘法和四元数还原，完整评分全部路径点；没有改成平面近似、窗口搜索或复用旧目标。原有 0.20 m 离轨判断、前视距离、评分与平分时保留首点的顺序不变，所有足迹和制动检查继续执行。当前路径点的独立消息头原本不参与变换选择，输出沿用所查询 TF 的头信息。

新的原计算对照覆盖 4,891 组：替换路径、空 / 单点、重复 / 交叉、变换变化、roll / pitch、非单位四元数及阈值相邻浮点数；接受 / 拒绝及返回位姿、头信息逐位一致。新 Humble Release 构建的 12 项 CTest 全部通过，包含原生 MPPI 公共 API 的 198 组命令限制检查与既有缓存 ROS 探针。没有把上一阶段额外的 28 个 ROS 场景重新计为本轮执行。

本机组件串行 ABBA，每臂两次新进程、每次 100 预热周期。100 / 1,000 / 10,000 点路径分别评分 200,000 / 20,000 / 2,000 周期，平均线程 CPU 为 0.006824→0.004641 / 0.077616→0.042125 / 1.159690→0.427334 ms（−32.0% / −45.7% / −63.2%）。每周期替换 1,000 点路径并计入子类预处理时为 0.080157→0.049116 ms（−38.7%）。所有比较臂的语料哈希和有序输出指纹一致。

首次预处理增加成本；完整最近点扫描仍为 O(N)。上述计时不覆盖原生 MPPI `setPlan`、TF 获取、地图、制动、ROS、控制周期或导航，不能把它与关联缓存的比例相加。源码、记录见 [分项结果](evidence/navigation-path-target/summary.json)、[逐次记录](evidence/navigation-path-target/records.json)，完整语料、构建与验证见 [本地报告](/home/th1rt3en/Documents/Codex/2026-10-10/outputs/jetson-path-target/report.md)。本轮未连接 Jetson，首次全局规划与整机实时性对照仍待板端验证。

## 2026-10-10 再一轮：有上限的连续点索引

[SpatialPointIndex](../src/duojin02_navigation/include/duojin02_navigation/guard_query.hpp) 在紧凑点集上使用连续桶偏移 / 原始索引，避免近邻查询反复哈希；最多 65,536 格，且不超过 `16 × max(64, 点数)`。宽 / 稀疏范围继续用原哈希桶。首 / 中 / 末点范围只可提前证明超限，批准连续存储前仍遍历全部点；隐藏离群点另有负例。桶遍历与桶内原始索引顺序、精确 `hypot`、点半径及所有原安全判断保持，未改变查询半径、20 Hz 周期或 YAML。
