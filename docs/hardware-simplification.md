# hardware-only 减法记录

日期：2026-10-06。基于 `b3f68de`，本轮改动仅在 `hardware-only` 工作树。

## 当前范围

统一平台为 Jetson Orin Nano / Ubuntu 22.04 / ROS 2 Humble，硬件为麦克纳姆底盘及其 IMU、N10Plus 串口雷达。项目包从 10 个减至 6 个：底盘驱动、雷达驱动、描述、bringup、SLAM 工具、遥控。开放接口使用标准 ROS 消息、TF、Nav2 Action 和 SLAM 服务。

完整删除相机、AprilTag、机械臂 G-code、任务包装、相关自定义消息和启动入口；移除 Python 相机依赖和额外的 AprilTag 编译链。镜像仍按官方 Nav2 / PCL 等依赖安装所需系统库，不能以安装目录里出现 OpenCV 就判断相机功能仍然存在。

雷达固定为当前 460800 波特率、108 字节双回波协议、540 格扫描及本机角度方向。删除其他型号、网络 / PCAP、设备服务、设备时间、矩阵变换、MultiEcho 输出和旧配置兼容。保留串口路径、话题名、坐标系及距离过滤配置；不为未知设备或错误配置增加降级分支。

## 热路径与运行边界

底盘反馈状态由一把互斥锁保护，删除同一状态上的重复原子操作；健康检查与帧读取合并为一次加锁。复用速度命令缓冲区，删除每次发送的临时分配、未使用的原始反馈副本和重复 IMU 复制。地图服务等待使用 ROS 自带的 future 等待函数。

雷达原始包改为固定长度数组。发布只用一个工作线程，保持帧顺序并在退出时排空队列；删除通用线程池、future 及额外 ROS 执行器线程。LaserScan 直接遍历本帧点云，只为标准 PointCloud2 执行一次转换。距离只在解码点进入本帧时过滤，内部不重复校验同一份数据。

保留真实外部边界：串口分段读取、协议长度 / 校验和、设备断连、底盘静默恢复、跨线程生命周期，以及速度命令到 int16 协议的有限值检查和饱和。项目维护的启动参数不再做多层检查和修复。数学角度边界、时间恢复和线程同步不属于可以随意删除的配置防御。

回归中修复了三处帧行为：不再丢弃少于 50 点的合法扫描，空帧也会更新下游；首包在中途跨零时正确记录末端角度，避免误发部分帧；维持既有浮点角度分格约定并统一 ±π 接缝。扫描经过角度重排，`time_increment=0`，没有可靠的逐束采集时间。

本次 AMD64 Release 雷达可执行文件从 2,512,672 字节减至 745,296 字节，约减少 70%。这是代码体积数据；未测量 Orin 上的 CPU 开销或实时延迟，不能据此推断运行提速比例。
